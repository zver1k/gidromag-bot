# 🤖 Gidromag Telegram Bot

Telegram бот для загрузки фотографий, видео и документов оборудования на Яндекс.Диск с организацией по накладным.

## 🚀 Возможности

- 📸 Загрузка фотографий на Яндекс.Диск (JPG, JPEG, PNG, JFIF → автоконвертация в JPG, сжатие > 5 MB)
- 🎥 Загрузка видео на Яндекс.Диск (до 4K, до 500 MB)
- 📄 Загрузка документов на Яндекс.Диск (PDF, Word, Excel до 50 MB)
- 📋 Организация по номерам накладных (кириллица, латиница, цифры)
- 👥 Управление доступом пользователей (хранение на Яндекс.Диске)
- 📊 Статистика использования (хранится в SQLite, сохраняется при перезапуске)
- 🔁 Автоповтор при сбоях сети (3 попытки с экспоненциальной задержкой)
- ⏱ Rate limiting: не более 20 файлов в минуту на пользователя
- 🔍 Дедупликация файлов по MD5 в рамках накладной
- 🧹 Автоматическая очистка устаревших сессий раз в час
- ⚡ Интерактивное inline-меню
- ⏳ Автосброс накладной после 10 минут бездействия

## 📋 Команды бота

### Основные команды
- `/start` — Начать работу с новой накладной
- `/reset` — Сбросить текущую накладную
- `/cancel` — Псевдоним `/reset`
- `/current` — Показать текущую накладную
- `/stats` — Статистика бота
- `/status` — Статус бота и сервисов
- `/help` — Справка
- `/userinfo` — Информация о пользователе
- `/menu` — Inline-меню

### Административные команды
- `/adduser <ID>` — Добавить пользователя
- `/removeuser <ID>` — Удалить пользователя
- `/listusers` — Список всех пользователей
- `/cleanup` — Очистка временных файлов

## 🔐 Управление доступом

1. Пользователь узнаёт свой ID: `/start` → @userinfobot
2. Администратор: `/adduser 123456789`
3. Удалить: `/removeuser 123456789`

> Список хранится на Яндекс.Диске (`/Фото оборудования/allowed_users.txt`) и синхронизируется при каждом входе.

## 📖 Как использовать

1. `/start`
2. Введите номер накладной (3–50 символов: кириллица, латиница, цифры, пробел, дефис, подчёркивание)
3. Отправляйте фото, видео или документы — они сохраняются в папку по номеру накладной
4. `/reset` для завершения накладной

## ⚙️ Установка и настройка

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Переменные окружения
```bash
export TELEGRAM_TOKEN="your_telegram_bot_token"
export YANDEX_DISK_TOKEN="your_yandex_disk_token"
export WEBHOOK_URL="https://your-domain.com/"
export PORT="8443"
```

### 3. Администраторы
В `config.py`:
```python
ADMIN_IDS = [
    123456789,  # Ваш ID
]
```

### 4. Запуск
```bash
python bot.py
```

База данных `bot_data.db` создаётся автоматически при первом запуске.

## 📁 Структура проекта

```
gidromag-bot/
├── bot.py                  # Точка входа, регистрация обработчиков
├── config.py               # Конфигурация и константы
├── database.py             # SQLite (aiosqlite): сессии, статистика, хеши
├── requirements.txt        # Зависимости Python
├── runtime.txt             # Версия Python для Render
├── handlers/
│   ├── commands.py         # Команды: start, reset, stats, status, help и др.
│   ├── media.py            # Загрузка фото, видео, документов
│   └── admin.py            # Административные команды
├── services/
│   ├── yadisk_service.py   # Яндекс.Диск API с retry-логикой
│   ├── users_service.py    # Управление списком пользователей
│   └── session_service.py  # Управление сессиями + фоновая очистка
└── utils/
    ├── rate_limiter.py     # Ограничение частоты загрузок
    └── image_utils.py      # Сжатие фото, JFIF→JPG конвертация (Pillow) + MD5-хеш
```

> `bot_stats.json` создаётся автоматически на Яндекс.Диске (`/Фото оборудования/bot_stats.json`) и обновляется каждые 15 минут.

Также добавлен `stats_service.py` в `services/`.

## 🔧 Конфигурация (`config.py`)

| Параметр | Значение | Описание |
|---|---|---|
| `MAX_FILE_SIZE` | 10 MB | Максимальный размер фото |
| `MAX_VIDEO_SIZE` | 500 MB | Максимальный размер видео |
| `MAX_DOCUMENT_SIZE` | 50 MB | Максимальный размер документов |
| `MAX_PHOTOS_PER_INVOICE` | 50 | Максимум фото на накладную |
| `MAX_VIDEOS_PER_INVOICE` | 10 | Максимум видео на накладную |
| `MAX_DOCUMENTS_PER_INVOICE` | 20 | Максимум документов на накладную |
| `BASE_FOLDER` | `Фото оборудования` | Базовая папка на Яндекс.Диске |
| `INACTIVITY_TIMEOUT_SECONDS` | 600 | Таймаут бездействия (сек) |
| `INVOICE_PATTERN` | `^[а-яА-ЯёЁa-zA-Z0-9 _-]{3,50}$` | Маска номера накладной |

## 🚨 Безопасность

- Whitelist-доступ: только разрешённые пользователи
- Ленивая синхронизация списка с Яндекс.Диска при каждом входе
- Изменения `ALLOWED_USERS` через `asyncio.Lock`
- Audit log для `/adduser` и `/removeuser` (запись в лог с ID администратора)
- Валидация форматов, размеров и номеров накладных
- Дедупликация файлов по MD5
- Rate limiting: 20 файлов/мин на пользователя

### v5.1.0 — Поддержка JFIF

### v5.0.0 — Рефакторинг и улучшения
- ✅ **SQLite** — сессии, статистика и хеши файлов хранятся в `bot_data.db`
- ✅ **Персистентная статистика** — счётчики сохраняются в `bot_stats.json` на Яндекс.Диске каждые 15 минут и при завершении; восстанавливаются после рестарта (в т.ч. на Render)
- ✅ **Rate limiting** — не более 20 загрузок в минуту на пользователя
- ✅ **Retry-логика** — до 3 попыток с задержками 1/2/4 сек. при сетевых сбоях Яндекс.Диска
- ✅ **Автоочистка памяти** — фоновая задача каждый час удаляет устаревшие сессии из памяти и БД
- ✅ **Модульная архитектура** — `handlers/`, `services/`, `utils/` вместо одного `bot.py` на 1400 строк
- ✅ **Дедупликация** — MD5-хеш каждого файла; повторный файл в той же накладной отклоняется
- ✅ **Сжатие фото** — фотографии > 5 MB автоматически сжимаются через Pillow перед загрузкой
- ✅ **Audit log** — `/adduser` и `/removeuser` логируют ID администратора
